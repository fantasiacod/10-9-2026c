١. قبل أن تبدأ — المتطلبات

الموقع يحتاج استضافة تشغّل PHP. هذه النقطة أساسية ولا بديل عنها.

نوع الاستضافةهل تعمل؟ملاحظة
استضافة cPanel تدعم PHPتعملالخيار الأسهل
Render (نوع Docker)تعمليحتاج ملف Dockerfile المرفق
Render (نوع Static Site)لا تعمللا يشغّل PHP

تحذير مهم لا ترفع المشروع على GitHub Pages أو أي استضافة ملفات ثابتة. في هذه الحالة تُعرض ملفات PHP كنصوص بدل تنفيذها، وهذا يكشف ملف بيانات الدخول للجميع.

٢. هيكل ملفات المشروع

حافظ على هذا الترتيب تماماً. تغيير أماكن المجلدات يوقف الموقع.

site_ready_v48/
├── index.php          ← الصفحة الرئيسية (افتحها بهذا الاسم)
├── login.php          ← تسجيل الدخول
├── admin.php          ← لوحة التحكم
├── debug.php          ← صفحة التشخيص (احذفها بعد التركيب)
├── Dockerfile         ← مطلوب لـ Render فقط
├── .htaccess          ← إعدادات الحماية والكاش
│
├── api/               ← ملفات الخادم (لا تعدّلها)
│   ├── auth.php       ← تسجيل الدخول والجلسات
│   ├── storage.php    ← طبقة قواعد البيانات
│   ├── get_data.php   ← قراءة بيانات الموقع
│   ├── save_data.php  ← حفظ التعديلات
│   ├── upload.php     ← رفع الصور
│   ├── db_config.php  ← إعداد قاعدة البيانات
│   └── health.php     ← فحص حالة النظام
│
├── data/              ← بيانات الموقع وكلمة المرور  (مهم: صلاحية كتابة)
├── uploads/           ← الصور المرفوعة              (مهم: صلاحية كتابة)
├── css/  js/  assets/ ← التصميم والسكربتات والزخارف
└── seed/              ← بيانات البداية الافتراضية
مجلدان يحتاجان صلاحية الكتابة data و uploads يجب أن تكون صلاحيتهما 755 أو 775. بدون ذلك لن يستطيع الموقع حفظ الإعدادات ولا الصور.

٣. رفع الملفات على GitHub

هذه الخطوة مطلوبة فقط إذا كنت ستنشر على Render. لاستضافة cPanel انتقل للقسم ٥.

  1. افتح github.com وسجّل الدخول، ثم اضغط + في الأعلى واختر New repository.
  2. اكتب اسماً بالإنجليزية بلا مسافات، مثل greeting-cards، واختر Private، ثم Create repository.
  3. في الصفحة التالية اضغط الرابط uploading an existing file.
  4. فُك ضغط ملف المشروع أولاً، ثم اسحب محتويات مجلد site_ready_v48 (لا المجلد نفسه) إلى نافذة الرفع. يجب أن يظهر index.php في المستوى الأول.
  5. اكتب وصفاً في خانة Commit changes ثم اضغط الزر الأخضر Commit changes.
أكثر خطأ شائع رفع المجلد site_ready_v48 نفسه بدل محتوياته. النتيجة أن الملفات تصبح داخل مجلد فرعي فلا تجدها الاستضافة ويظهر خطأ Not Found. تأكد أن index.php وDockerfile ظاهران مباشرة في الصفحة الأولى للمستودع.

٤. النشر على Render

  1. افتح render.com وسجّل الدخول بحساب GitHub.
  2. اضغط New + ثم اختر Web Service.
  3. اختر المستودع الذي رفعته، ثم Connect.
  4. في خانة Language اختر Docker.
    لا تختر Static Site — لن يعمل الموقع.
  5. اترك باقي الإعدادات كما هي واضغط Deploy Web Service.
  6. انتظر حتى تتحول الحالة إلى Live (عادة ٣ إلى ٥ دقائق).
مهم جداً على Render: القرص الدائم Render يمسح ملفات الموقع مع كل عملية نشر. بدون قرص دائم ستفقد إعداداتك وكلمة مرور الأدمن وتعود إلى admin/admin.
الحل: اربط الموقع بقاعدة بيانات خارجية (Supabase أو MySQL) من القسم ٦، عندها تُحفظ بياناتك خارج Render ولا تتأثر بالنشر.

٥. الرفع على استضافة عادية (cPanel / FTP)

  1. ادخل لوحة تحكم الاستضافة واختر File Manager (مدير الملفات).
  2. افتح مجلد public_html — وهو المجلد الذي يظهر للزوار.
  3. احذف أي ملفات قديمة للموقع إن وُجدت، خاصة index.html.
  4. اضغط Upload وارفع ملف المشروع المضغوط، ثم اضغط عليه بالزر الأيمن واختر Extract.
  5. تأكد أن index.php صار مباشرة داخل public_html. إن ظهر مجلد site_ready_v48 بداخله الملفات، ادخله وانقل محتوياته للأعلى.
  6. اضبط الصلاحيات: اضغط بالزر الأيمن على مجلد data ثم Permissions واجعلها 755. كرر نفس الشيء مع uploads.
  7. افتح موقعك في المتصفح للتأكد من ظهور الصفحة.
ملف Dockerfile هذا الملف يخص Render فقط. وجوده على استضافة cPanel لا يضر ولا يؤثر على شيء.

٦. إنشاء قاعدة البيانات

اختر واحدة فقط. إن كانت استضافتك عادية ودائمة فـ MySQL أبسط، وإن كانت على Render فاختر Supabase.

أ) إنشاء قاعدة MySQL على cPanel

  1. من لوحة cPanel افتح MySQL Databases.
  2. اكتب اسم قاعدة البيانات واضغط Create Database، وسجّل الاسم الكامل الذي يظهر.
  3. انزل إلى Add New User، أنشئ مستخدماً بكلمة مرور قوية، واحفظهما.
  4. من Add User To Database اربط المستخدم بالقاعدة، وامنحه ALL PRIVILEGES.

ستحتاج لاحقاً: اسم القاعدة، اسم المستخدم، كلمة المرور، والخادم (غالباً localhost).

ب) إنشاء مشروع Supabase

  1. افتح supabase.com وسجّل حساباً مجانياً.
  2. اضغط New Project، اختر اسماً وكلمة مرور لقاعدة البيانات واحفظها.
  3. انتظر اكتمال التجهيز (دقيقتان تقريباً).
  4. افتح Project Settings ← API وانسخ:
    • Project URL — يشبه https://xxxx.supabase.co
    • anon public — المفتاح الطويل الذي يبدأ بـ eyJ...
  5. افتح SQL Editor واضغط New query، ثم الصق كود SQL الذي ستنسخه من لوحة التحكم (يوجد زر نسخ الكود بجانبه) واضغط Run.
لا تستخدم مفتاح service_role في صفحة API ستجد مفتاحين. استخدم anon public فقط. مفتاح service_role سري ويتجاوز كل الحمايات، ولا يصلح للاستخدام هنا.

٧. الربط من لوحة التحكم

  1. افتح موقعك.com/login.php.
  2. سجّل الدخول ببيانات البداية: المستخدم admin وكلمة المرور admin.
  3. من القائمة الجانبية اختر قاعدة البيانات والربط السحابي.
  4. راجع فحص حالة النظام في أعلى الصفحة، وأصلح أي بند أحمر قبل المتابعة.
  5. اختر نوع قاعدة البيانات، واملأ البيانات، ثم اضغط اتصال وحفظ.
  6. عند ظهور رسالة نجاح خضراء يكون الربط قد تم ونُقلت بياناتك تلقائياً.
الطريقة الأسرع لـ MySQL و PostgreSQL إن أعطتك الاستضافة نص اتصال كامل (Connection String) مثل mysql://user:pass@host:3306/dbname، الصقه في الحقل المخصص واضغط اتصال تلقائي. سيتم استخراج كل البيانات وإنشاء الجداول تلقائياً بلا أي خطوة أخرى.

٨. تأمين الموقع بعد التركيب

  1. غيّر بيانات الدخول فوراً. من لوحة التحكم: حسابي ← تغيير كلمة المرور. اكتب كلمة المرور الحالية admin، ثم اسم مستخدم جديداً وكلمة مرور لا تقل عن ٨ أحرف.
  2. احذف ملف debug.php من الاستضافة. مهمته التشخيص فقط، ولا داعي لبقائه متاحاً للعامة.
  3. فعّل شهادة SSL من لوحة الاستضافة ليعمل الموقع على https. بدونها تنتقل كلمة المرور بلا تشفير. (على Render تكون مفعّلة تلقائياً.)
بيانات الدخول الافتراضية المستخدم admin وكلمة المرور admin. سيظهر لك شريط أحمر في لوحة التحكم ما دمت لم تغيّرها. لا تترك الموقع يعمل بها.

٩. حل المشاكل الشائعة

المشكلةالسبب والحل
Not Found عند فتح الموقع الملفات داخل مجلد فرعي. تأكد أن index.php في المستوى الأول، وليس داخل مجلد site_ready_v48.
يظهر كود PHP كنص في الصفحة الاستضافة لا تشغّل PHP. انتقل لاستضافة تدعمه، أو على Render أعد إنشاء الخدمة بنوع Docker.
تسجيل الدخول لا يعمل غالباً نفس السبب السابق. افتح موقعك.com/debug.php وسيخبرك بالسبب بدقة.
التعديلات لا تُحفظ مجلد data غير قابل للكتابة. اجعل صلاحيته 755 أو 775.
رفع الصور يفشل مجلد uploads غير قابل للكتابة. اضبط صلاحيته، وإن تعذّر فالموقع سيحفظ الصور داخل قاعدة البيانات تلقائياً (بحد ٢ ميجابايت للصورة).
«جدول site_configs غير موجود» لم تُشغّل كود SQL في Supabase. انسخه من لوحة التحكم وشغّله في SQL Editor ثم أعد المحاولة.
التعديلات لا تظهر على الجوال تأكد أنك تفتح index.php لا index.html، وأنك حذفت الملفات القديمة من الاستضافة. ثم امسح كاش المتصفح مرة واحدة.
عادت الإعدادات للوضع الافتراضي بعد النشر خاص بـ Render: تُمسح الملفات مع كل نشر. اربط الموقع بـ Supabase أو MySQL خارجي لتبقى البيانات.
أداتان للتشخيص داخل البرنامج
• فحص حالة النظام — داخل لوحة التحكم، يفحص الاستضافة ويشرح حل كل مشكلة.
• debug.php — افتحه على الجهاز الذي يواجه المشكلة، يقارن بيانات الخادم بما يراه الجهاز ويحدد السبب، وفيه زر لمسح الكاش المحلي.
